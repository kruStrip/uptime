# Uptime

Внешний монитор доступности сайтов. Раз в 5 минут GitHub открывает четыре страницы
и проверяет, что они отвечают кодом 200 и содержат ожидаемый текст. Если нет —
создаётся issue и приходит сообщение в Telegram.

Проверка идёт снаружи, а не с сервера: 14.11.2026 nginx на сервере залип так, что
изнутри всё отвечало 200, а снаружи не было даже TLS-ответа.

## Что происходит при аварии

- Создаётся один issue с меткой `uptime` и приходит письмо от GitHub.
- Пока issue открыт, повторов нет — сообщения не спамят каждые 5 минут.
- Когда все страницы снова отвечают, issue закрывается автоматически, а в Telegram
  приходит «Сайт снова работает».

## Алерты в Telegram

Секреты: **Settings → Secrets and variables → Actions → New repository secret**.

- `TELEGRAM_BOT_TOKEN` — токен бота из [@BotFather](https://t.me/BotFather).
- `TELEGRAM_CHAT_ID` — ваш числовой id: напишите [@userinfobot](https://t.me/userinfobot),
  он ответит числом вида `123456789`.

Пока секретов нет, проверка работает, но алерты видны только в issue.

## Ручной запуск

Actions → Uptime → Run workflow. Галочка `test` создаёт тестовый issue, чтобы
проверить, что алерты доходят.

## Нюансы

- GitHub может задержать плановый запуск на несколько минут при высокой нагрузке —
  это нормально для бесплатного расписания.
- Публичный репозиторий выбран намеренно: в приватном каждый запуск списывает
  минимум минуту, и 5-минутная проверка не влезла бы в лимит 2000 минут в месяц.
